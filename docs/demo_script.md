## 3) 코드-화면 매칭 설명 — 클래스 & 자료구조

화면을 멈추거나 캡처해서 코드와 짝지어 설명하는 구간.

### 클래스 (화면의 "사물"이 곧 클래스 인스턴스)

| 화면에서 보이는 것 | 클래스 | 위치 |
|---|---|---|
| 조작하는 캐릭터 | `Player` | `entities/player.py` |
| 정찰하는 적 | `Enemy` | `entities/enemy.py` |
| 스테이지 4 보스 | `Boss` | `entities/boss.py` |
| 바닥/가시/출구/스위치/게이트 한 칸 | `Tile` | `world/tile.py` |
| 현재 플레이 중인 맵 전체 | `Stage` (보스전은 `BossStage`) | `world/stage.py`, `world/boss_stage.py` |
| 게임 플레이 화면 자체 | `GameScene` | `scenes/game_scene.py` |

> "화면에 보이는 캐릭터 하나하나, 그리고 게임 화면 자체가 모두 클래스의 인스턴스입니다. 예를 들어 지금 움직이는 이 캐릭터는 `Player` 클래스의 객체이고, 바닥 타일 하나하나는 `Tile` 클래스의 객체입니다. `GameScene`은 이 모든 객체들을 들고 있으면서 매 프레임 업데이트·그리기를 호출하는 역할을 합니다."

### 자료구조 — 시간 되감기는 스택(Stack)으로 구현

[Z 또는 X로 되감기 실행하는 장면을 다시 보여주며]

> "이 게임의 핵심 메커닉인 시간 되감기는 **스택** 자료구조로 구현되어 있습니다. `core/time_stack.py`의 `TimeStack` 클래스가 내부적으로 리스트(`self.history`)를 스택처럼 사용합니다."

```python
# core/time_stack.py
class TimeStack:
    def __init__(self, max_size=180):
        self.history = []          # 스택 역할을 하는 리스트

    def push(self, state):
        self.history.append(state.copy())   # 매 프레임 현재 상태를 쌓는다

    def pop(self):
        if len(self.history) > 0:
            return self.history.pop()        # 가장 최근(맨 위) 상태를 꺼내 되돌린다
        return None
```

> "매 프레임마다 `push()`로 현재 상태를 스택 맨 위에 쌓고, 되감기를 누르면 `pop()`으로 맨 위(가장 최근 시점)부터 꺼내서 그 상태로 되돌립니다. 후입선출(LIFO) 구조라서 '가장 최근 과거부터' 순서대로 되돌아가는 게 자연스럽게 보장됩니다."

[push되는 한 칸의 데이터 구조도 같이 보여줌]

> "스택에 쌓이는 값 하나는 `GameState`라는 객체입니다 (`core/game_state.py`). 플레이어 위치·속도·HP와, 적들의 상태를 담은 리스트(`enemies: list[EnemyState]`)를 함께 가지고 있어서, 한 번의 `pop()`으로 플레이어와 적을 동시에 그 시점으로 되돌릴 수 있습니다."

```python
# core/game_state.py
class GameState:
    def __init__(self, player_x, player_y, player_vx, player_vy, hp, rewind_count):
        self.player_x = player_x
        ...
        self.enemies = []   # EnemyState 객체들의 리스트
```

> "정리하면 — **클래스**는 화면의 캐릭터·타일·씬을 각각의 객체로 표현하고, **스택 자료구조**는 그 객체들의 상태를 시간 순서대로 쌓아 두었다가 거꾸로 꺼내면서 '시간 되감기'라는 기능을 구현합니다."
