# Time Backer 발표용 상세 설명

`docs/presentation_essentials.md`의 9개 항목을 발표·Q&A에서 바로 쓸 수 있게 풀어 쓴 버전.

---

## 1. 한 줄 소개

"실수해도 시간을 되돌려 다시 도전할 수 있는 2D 플랫포머." 단순히 쉬워지는 게 아니라, 제한된 되감기 횟수를 언제 쓸지 판단하는 전략적 선택이 재미의 핵심입니다.

## 2. 핵심 메커닉 — 시간 되감기

- **Z**: 약 2초 전(120프레임)으로 되돌림, **X**: 스테이지 시작 지점까지 전체 되돌림. 둘 다 스테이지당 5회 공통 자원을 소비합니다.
- 구현: 매 프레임 플레이어·적 상태를 `GameState`로 캡처해 `TimeStack`(스택)에 push, 되감기 시 pop해서 그대로 덮어씀.
- 디자인 결정 한 가지: **스위치는 되감기 대상에서 제외**했습니다. 처음엔 스위치도 같이 되돌렸는데, 퍼즐을 풀어놓고 다른 곳에서 실수해 되감기하면 스위치가 다시 꺼지는 게 불편해서, 한 번 켠 스위치는 영구히 유지되도록 바꿨습니다.

## 3. 게임 구성 — 4개 스테이지

1 Normal(기본 액션) → 2 Switch(A/B 스위치 퍼즐) → 3 Golem(고난도 적) → 4 Boss(Time Guardian).

맵은 코드에 좌표를 박지 않고 **Tiled 에디터로 만든 `.tmx`를 `pytmx`로 로드**합니다. 레벨 수정이 코드 수정 없이 가능하다는 점이 포인트입니다.

## 4. 기술 스택

Pygame(렌더링/입력) + **Pymunk**(물리 — 자체 충돌 코드 대신 엔진에 위임) + **Pytmx**(TMX 맵 로딩).

## 5. 아키텍처

```
scenes/   화면 전환 (start / game / end)
world/    스테이지·타일 데이터
entities/ player / enemy / boss
core/     시간 되감기 스택, 물리 래퍼
```

씬 흐름: `타이틀 → 게임(1→2→3→4) → 결과 → 타이틀`. 역할이 파일 단위로 명확히 나뉘어 있어 "보스 패턴만 수정" 같은 작업이 `boss.py` 한 파일로 끝납니다.

## 6. 기술적 문제와 해결 — "옆벽 통과 버그" (발표에서 가장 어필되는 부분)

벽 쪽으로 계속 이동하면 약 0.5초 만에 벽을 뚫고 지나가는 버그가 있었습니다. 원인은 **입력 처리가 매 프레임 속도를 무조건 덮어써서**, 물리 엔진(pymunk)이 한 프레임 동안 충돌로 속도를 막아도 다음 프레임에 다시 벽 쪽 속도가 주입되어 침투 보정을 이겨버리고, 결국 박스 절반 너비를 넘게 파고든 순간 충돌 방향이 뒤집혀 완전히 통과하는 것이었습니다. (리팩토링 전 원본 코드로도 동일하게 재현돼서, 스타일 정리와는 무관한 기존 버그임을 먼저 확인했습니다.)

해결은 물리 엔진만 믿지 않고, 매 프레임 물리 연산 후 사각형 겹침을 직접 검사해 옆벽 충돌이면 확실히 밀어내는 보정(`resolve_wall_collisions`)을 추가하는 것이었습니다. 이후 스위치로 열리는 게이트에서도 같은 문제가 재발해 추가로 수정했습니다 — 같은 원인의 버그가 다른 곳에서도 나타날 수 있다는 걸 직접 겪은 사례입니다.

## 7. 결과 화면 / 평가

클리어 타임 + 되감기 사용 횟수를 표시하고, 적게 쓸수록 별점이 높습니다(1회 이하 ★★★, 3회 이하 ★★☆, 그 이상 ★☆☆). 되감기를 "안전망"이 아니라 "아낄수록 좋은 자원"으로 만든 밸런스입니다.

## 8. 데모 시연 추천 순서

짧게 보여줄 거면 **스테이지 2(스위치 켜기 전/후 게이트 비교)**와 **스테이지 4(보스의 타임 리버스)** 두 장면이 메커닉을 가장 잘 보여줍니다. 대사는 `docs/demo_script.md` 참고.
